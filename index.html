05

Why AI, and why now

I am not leaving .NET. I am extending it. The platforms I have already built — service catalogs, document pipelines, event streams — are exactly where applied ML earns its keep.

A municipality portal already stores the text of applications, inspection notes, and generated licenses. A media catalog already moves through Kafka. Those are retrieval, ranking, and anomaly problems wearing enterprise clothes. I want to be the person who can still own the service boundary and the model that sits behind it.

The path I am on is deliberate: ML.NET and Semantic Kernel so intelligence can live next to C# services I already operate; Python when the experiment needs a looser loop; RAG before unconstrained generation; evaluation before a demo. Thirteen years of production bias is the advantage, not the baggage.

“The next runtime is not a rewrite. It is another process I can host, observe, and roll back.”

  1. Now ML.NET beside existing services

    In-process models for ranking, classification, and anomaly signals without standing up a separate ML stack.

  2. Next Semantic Kernel tool calling

    Agents that call the same C# service boundaries I already operate — not chat wrappers around a monolith.

  3. Then RAG over documents we already produce

    Licenses, inspection notes, and multilingual PDFs are retrieval problems before they are generation problems.

  4. Always Evaluate, observe, roll back

    No public copilot without traces, eval sets, and a kill switch. Production bias stays the default.

Route a citizen request

A transparent keyword model that maps free text to the same service boundaries I already ship in ASP.NET. In production this would be ML.NET or a grounded model behind the API — with a human in the loop when confidence is low. 

// Same idea, hosted next to the service I already operate
app.MapPost("/intents", async (Request text, IntentModel model) =>
{
    var scored = model.Predict(text);
    return scored.Confidence < 0.55
        ? Results.Json(new { route = "human-review", scored })
        : Results.Json(new { route = scored.Service, scored });
});
